# Frontend — Agent Instructions

루트 `AGENTS.md`를 함께 따른다. 기본 수정 소유 범위는 `frontend/**`; 백엔드·DB·루트 인프라 코드는 승인 없이 수정하지 않는다.

## 책임과 UI

- Next.js App Router, React, TypeScript, Tailwind를 사용한다. 정확한 의존성 버전은 `package.json`이 기준이다.
- Mobile First를 유지하고 모바일·데스크톱에서 읽기 쉬운 금융 정보 UI를 만든다. 새 화면/기능은 마크업 → 디자인 → 기능 연동 순으로 검토한다. 기존 화면의 오류 수정·성능 개선은 필요한 부분을 함께 수정·검증할 수 있으며 불필요한 단계 산출물을 만들지 않는다. 기존 컴포넌트·Typography·Spacing·버튼 패턴을 재사용한다.
- 접근성, 로딩·빈 화면·오류 상태, 버튼 중복 클릭, 네트워크 지연 및 재시도를 기능과 함께 검증한다.

## 인증·금융 불변조건

- Guest 7일 opaque Bearer와 회원 OAuth2/Access JWT/Refresh Cookie는 분리하여 처리한다. Guest 계정의 금융 내역을 회원 계정에 자동 합치지 않는다.
- 회원 Access는 메모리에서 관리하고, Refresh는 HttpOnly 쿠키·CSRF 및 현재 다중 탭 동시성 정책을 따른다. 활성 탭 중심 갱신이 정상적인 다른 탭·로그아웃·복귀 흐름을 깨지 않도록 한다.
- 클라이언트는 입력 검증·예상 금액을 표시할 수 있지만 최종 체결가·잔고·PnL·Margin·청산 여부를 임의로 확정하지 않는다.
- 금융 Decimal 값을 JavaScript 부동소수점으로 무분별하게 변환하지 않는다. 기존 decimal/BigInt 또는 서버 응답 계약을 활용한다.
- Browser는 Binance에 직접 연결하지 않고 Trading Server의 REST/WebSocket에서 시세·차트·호가를 받는다. 실행 중인 서버의 Runtime OpenAPI와 소스 커밋을 함께 확인한다. 구버전 실행본을 최신 계약으로 오인하지 않는다.
- 불확실한 거래 요청에는 기존 멱등성 키와 재확인 흐름을 유지한다. 응답이 없다고 무조건 새 주문을 전송하지 않는다.

## 검증 및 협업

- Backend API가 부족하면 계약·필요 변경을 보고하고, 해당 서비스 PR을 확인한다. 승인 없이 Backend 코드를 고치지 않는다.
- 기능에 필요한 기존 테스트와 `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 범위에 맞게 실행한다.
- Git·PR·기존 MD 갱신 제한은 루트 `AGENTS.md`를 따른다. 실행·환경변수는 [`README.md`](README.md)에 둔다.

## 방향별 레버리지·거래 상태

- 같은 종목의 LONG15배/SHORT7배처럼 독립 설정을 제공한다. Backend의 GET side 쿼리와 PUT side 본문을 따른다. 계정·종목·방향별 캐시, 로딩, 변경·오류 상태를 분리한다.
- 견적·주문은 해당 방향의 확인된 서버 레버리지를 사용한다. 반대 방향 값으로 전송하거나 미확인 기본값/undefined를 확정 설정처럼 표시하지 않는다. 한 방향 변경이 반대 방향과 다른 종목 설정을 덮어쓰면 안 된다.
- 설정 변경 시 절대 PnL, 담보, ROE, 예상 청산가의 차이를 올바르게 표시한다. 최종 계산·거래 허용 여부는 Backend를 따른다.
- 로그인 확인, 필수 재동의, 계정 생성 대기, 위험 작업 대기, 운영 검토, 조회 실패, 주문 거절, 결과 미확정, 접수·체결을 구분한다. 차단 이유와 다음 행동을 해당 화면에서 안내한다.
- LEDGER_MISMATCH는 원장 불일치 검토로 설명한다. 내부 예외나 원문 detail을 그대로 렌더링하지 않는다. 오류/미확정 안내는 읽을 시간을 제공하고 이력에서 확인 가능한 결과는 다시 찾을 수 있게 한다.
- 주문 mutation 자동 재전송·새 키 발급으로 불확실한 결과나 복구 차단을 우회하지 않는다. 이미 접수된 주문의 결과는 같은 키로 확인한다. 연결 상태를 엔진의 처리 완료와 혼동하지 않는다.

## 부드러운 화면과 검증

- 시세·차트·호가·포지션 손익·지갑·주문 입력의 갱신 범위를 구분한다. 시세마다 전체 화면 렌더링, 중복 구독/조회, 입력·포커스·스크롤 초기화를 피한다.
- 초기 로딩과 백그라운드 갱신을 구분하고 기존 화면을 불필요하게 지우지 않는다. 오래된 가격은 최신값처럼 표시하지 않는다. 계정/종목/회차 전환의 오래된 응답과 WS 이벤트는 새 화면에 적용하지 않는다.
- 체결·잔액을 낙관적으로 확정하지 않는다. 클릭 직후 접수 중 피드백은 제공하되 실제 위험 차단과 단순 조회 중 상태를 구분한다.
- 리렌더·긴 작업·입력 반응·중복 네트워크 요청은 대표 시나리오에서 개선 전후 측정한다. 화면에서 빠르게 보이는 것과 Backend의 체결 완료 시간을 분리한다.
- API mock/단위 테스트와 실제 회원 로그인→양방향 진입→부분/전체청산 E2E를 구분한다. Backend가 막히면 UI에서 가짜 성공을 만들지 말고 의존 이슈로 보고한다.
- 현재 증거금 비중과 기간별 확정 성과를 구분한다. LONG/SHORT 합산 거래대금, 수수료, 순손익, 현재 미실현손익을 정확히 표시하고 자본조정·격리 정산 조정을 투자 수익으로 꾸미지 않는다.
